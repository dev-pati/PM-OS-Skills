PATI Product Development Framework — request to adopted evidence, two gates, no shortcut. Source: Second Brain/Knowledge/playbooks/product-development-framework.md (updated 2026-09-04)

Two gates, no spec before both

  • Gate 1 Business B1-B9: persona, workaround cost, problem, KPI, BL id, adoption hypothesis, unused signal, smallest version, cost of not building.
  • Gate 2 Connection eight planes 0-7, forward and reverse trace.
  • Killing or parking is a successful gate outcome.
  • Every deferred seam costs a TD- or BL- id.

Evidence beats assertion

  • Precedence: runtime > commit > chat > none. Never collapse the classes.
  • Code beats docs; runtime beats code. A disagreement is a finding, not a rewrite.
  • Full verification runs once, at the end. Focused tests may run during work.
  • Tests that copy source are still documentation (TD-12).

Shipped is not adopted

  • Adoption re-checks B6 (who opens it, how often) and B7 (how we learn nobody uses it).
  • Incidents are measured before corrected: ghost-ads 25/08/2026, 27 intended ads became 42 live.
  • Each incident buys a structural ordering rule, not a patch.
  • Prevention controls re-enter the spine, closing the loop.
